# Documentation strategy

Career OS should remain understandable independent of whichever development methodology happens to be fashionable.

## Durable project knowledge

The durable layer is ordinary, inspectable project documentation:
- career direction
- design principles
- decision log
- v0 contract
- runtime behavior instructions
- acceptance scenarios

## Methodologies are temporary exoskeletons

Spec Kit and SPDD were used as experiments to pressure-test implementation handoff.

The comparison found useful ideas in both, but neither is retained as ongoing project machinery.

Future methodology experiments should:
- start from the same frozen source
- remain isolated from each other
- be evaluated for clarity, implementation readiness, and maintenance burden
- produce changes only when they materially improve canonical docs

Adrien's separate process-free documentation project may later be compared against this document set. It should not be introduced as a third simultaneous live methodology merely to make Career OS conform to it.
